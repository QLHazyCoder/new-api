## 3. 白名单、违规次数与封禁

- [x] 白名单命中写审计和类型 8 日志，但不拦截、不计数。
- [x] 观察模式命中只记录，不拦截、不计数、不封禁。
- [x] 普通用户命中在用户行锁事务中原子增加违规次数。
- [x] 第 5 次有效命中只封禁一次，更新认证版本并撤销会话。
- [x] 管理员可编辑或清零次数，白名单开关在同一用户编辑抽屉维护。
- [x] 所有封禁和用户编辑路径均不修改 quota 或余额。
- [x] 普通用户管理“启用”和专用解封共享行锁事务，启用时显式清零当前违规次数。
- [x] 禁用用户启用时只递增一次 auth_version、刷新认证缓存并撤销旧会话；已启用用户重复启用不重复刷新。
- [x] 启用/解封写入 `sensitive_word.enable_reset` 管理审计，记录状态/次数前后值、入口来源和 `balance_changed:false`。

阶段自检：

- [x] 第 5 次后会话撤销，之后不重复封禁。
- [x] 审计事件的前后 quota 快照相同，日志明确写入 balance_changed:false。
- [x] 管理员清零违规次数不删除历史证据。
- [x] 第五次封禁后重新启用会从第 1 次重新计数，历史审计事件数量和内容保持不变。
- [x] 手工禁用且带有违规次数的用户启用同样清零；白名单状态保持不变。
- [x] 重复启用不会递增认证版本或撤销启用后新建的会话。
